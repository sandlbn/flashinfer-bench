# Fix 5: The tile/strategy the selector chose is wrong for your shape

Fixes 1-4 change how you *call* oneDNN. This changes what kernel it *generates* — for your
shape only. Use it when the call is already clean and the GEMM is still slow. It requires
rebuilding oneDNN and shipping that build.

Intel GPU GEMMs are JIT-generated by gemmstone from a shape-gated catalog of strategy
descriptors. The selection is observable:

```bash
ONEDNN_VERBOSE=debuginfo=5 python repro.py 2>&1 | grep "gpu,gemm"
```

```
consider:F gemm BBS T@4N@8N 32 64 at16x2+m64@48 am32+m32@64 aB wg 8x4 ... ,score:<n>
consider:F gemm BBS T@4N@8N 64 40 at16+m64@48  am32+m32@56 aB wg 4x8 ... ,score:<n>
kernel:  gemm BB[SB] T@16N@16N 32 64 ... wg 8x4 sys xaf ...
```

- `consider:` lines are catalog entries evaluated against your problem, each scored.
  **Lowest score wins**; the `kernel:` line confirms what was generated.
- The descriptor reads as tile and work-group shape: `32 64` is the tile, `wg 8x4` the
  work-group, `grf256` the register mode, `sys` systolic/XMX.

**To change it**, add or adjust an entry in
`tmp/oneDNN/src/gpu/intel/gemm/jit/selector/db/kernel.db`, gated on your precision,
transpose pattern and shape range:

```
{{'C', "gemm", {"B","B","S"}, {"N","T","N"}},   // bf16 x bf16 -> fp32 acc, N/T/N
 { ... shape gates, e.g. {-1, 8, -1} ... },     // applies only in this range
 "ab2 ab8 ab l4 cab1 wg 4x4 int sr",            // strategy string
 { 8, ..., {32,16,8}, {4,4,1}, ... }},          // unroll, tiles, work-group
```

Entries are shape-scoped. `generator/strategy_parser.cpp` defines the strategy-string
grammar. There is no runtime override — the catalog is compiled in (`dev_getenv` exposes
only generator debug switches).

Procedure:

1. Confirm by measurement that a different tile is faster for your shape.
2. Build with `scripts/build_onednn.py` into its own prefix (`optimize-onednn` SKILL.md,
   "check the two oneDNN versions") and point `FIB_ONEDNN_DIR` at it. `environment.libs`
   records `onednn` as `version+commit (resolved path)`, so a rebuilt library is
   distinguishable from a released one; still say what you changed in the solution's
   `description`.
3. Send the catalog entry upstream — it is shape-gated data and benefits everyone on that
   part.
